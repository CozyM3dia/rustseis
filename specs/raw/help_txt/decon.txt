Spiking/Predictive Deconvolution
Spiking/Predictive Deconvolution designs and applies
spiking or predictive deconvolution operators using the
Wiener-Levinson, least square algorithm. As an option these
ﬁlters can be applied in a phase or amplitude only mode.

Theory
The recorded seismic signal may be considered as the
convolution of the source signal with the instruments, the
geophones, and the response of the Earth. The Earth
response includes some undesirable effects, such as
reverberation, attenuation, and ghosting. The objective of
deconvolution is to estimate these effects as linear ﬁlters, and
then design and apply inverse ﬁlters.
After deconvolution the data may be optionally ﬁltered with a
bandpass ﬁlter. However, unless you have chosen phase only
or amplitude only ﬁlter application, bandpass ﬁltering can be
applied subsequently with Bandpass Filter more efﬁciently.

Usage
Design windows are interpolated between locations and
extrapolated, as constant, outside speciﬁed location ranges.
With multiple deconvolution operators, the ﬁrst is applied
from the beginning of the trace to the end of the ﬁrst design
window, then with decreasing linear taper to the beginning of
the second design window. If two design windows overlap, the
operator designed for the ﬁrst window is applied in the ﬁrst
window down to the zone of overlap. The operator designed
from the second window will be applied in the second window
below the zone of overlap. Within the zone of overlap, an
operator is interpolated between the operator designed in the
ﬁrst window and the operator designed in the second
window. We recommend that any gap between adjacent
windows or overlap zones between windows be at least 100
ms in length to avoid abrupt changes in operator
characteristics.
You can specify up to ten different deconvolution design
windows. The number of design windows must match the
number of operators. You must specify the desired

Parameters
Type of deconvolution
Select how the deconvolution operators will be designed and
applied. These choices include:
• Minimum phase spiking applies a traditional WienerLevinson spiking deconvolution.
• Minimum phase predictive applies a traditional
Wiener-Levinson predictive deconvolution.
• Phase connection only applies a Wiener-Levinson
decon without spectral whitening. Mute zones will be ﬁltered by the phasing correction.
• Zero phase spiking applies a Wiener-Levinson decon
without phase.
Decon operator length(s)
Enter the deconvolution operator length, in ms. The operator
length determines how much of the autocorrelation to use. If
more than one deconvolution operator is used, separate the
operators by commas.
Operator prediction distance(s)
This appears if Minimum phase predictive to Type of
deconvolution. Enter the operator prediction distance(s) to
apply to the input data. The prediction length is the length of
the prediction window, in ms. If more than one deconvolution
operator is used, separate the operators by commas.
Is prediction distance water relative?
This appears if Minimum phase predictive to Type of
deconvolution. Select Yes if the prediction distance(s) are
relative to water bottom time. Select No if the prediction
distance(s) are absolute.
Apply prediction ﬁlter correction?
This appears if Minimum phase predictive to Type of
deconvolution. Select Yes to make a correction for a
prediction window that contains the ﬁrst period peg-leg
multiple. This correction is only appropriate for shot and

Apply user speciﬁed taper?
Select Yes to enter a user speciﬁed taper length. This taper is
applied to the design gate prior to autocorrelation. Select No
to use a taper of 1/2 the minimum operator length.
Taper length in ms
This appears if Yes to Apply user speciﬁed taper. Enter the
taper length in ms. This taper is applied to the design gate
prior to autocorrelation.
Operator ’white noise’ level(s)
Enter the white noise value, in percent for each design gate.
This operator speciﬁes what percentage of white noise is
added to the original spike response. If more than one
deconvolution operator is to be used, separate the operators
by commas.

Output traces or ﬁlters
This appears if either Traditional Wiener-Levinson Spiking
or Predictive Decon to Type of deconvolution. Select an
option to output the ﬁlter operator for application to an
alternate dataset or for diagnostics. The choices are:
• Normal decon output outputs deconvolved traces. This
is the normal mode of operation.
• Filter operator output outputs ﬁlter operators instead
of deconvolved traces. The ﬁlter output is a normal trace
dataset with the same headers as the input traces.
• Autocorrelation output outputs autocorrelations computed over the decon design gate(s) instead of deconvolved traces. The autocorrelation output is a normal
trace dataset with the same headers as the input traces.
This option allows the derived ﬁlters or autocorrelations
for each input window to be output instead of the ﬁltered
traces. The ﬁlter/autocorr output is a normal trace
dataset with the same headers as the input traces. If
there is only one design window, the ﬁlter/autocorr is
output starting at the ﬁrst sample. If there are more than
one design windows, then the ﬁlter/autocorr is output
starting at the ﬁrst sample of each window.
This option allows for derivation of ﬁlters on a specially
conditioned dataset. You can apply the ﬁlters to the
original dataset by using Filter Application. The
number and sort of traces must agree.
