2D/3D Maximum Power Autostatics (Old)
Maximum Power Autostatics computes source and receiver
residual statics by maximizing the CDP stack power.

Theory
Maximum Power Autostatics can be effective in poor signalto-noise data. However, this process works well for a wide
range of data quality, if the velocity errors are reasonably
small. For a general discussion of input requirements,
database entries, and how residual statics are applied, refer
to the Residual Statics Overview.
Maximum Power Autostatics uses a modiﬁcation of the
method described in Ronen and Claerbout’s paper. For each
CDP, you build an initial pilot trace model from various time
gates of surrounding traces. Pilot traces are formed for each
time gate by ﬂattening all traces along the autostatics horizon
over the number of CDPs speciﬁed in the autostatics horizon
ﬁle by Smash for 2D, and over the number of CDPs speciﬁed
by the inline and crossline smash for 3D in the menu. All of
these traces are then summed to form a single pilot trace. A
given trace from an active CDP (center CDP unless near a
survey boundary) is subtracted from the single pilot trace to
form an updated pilot trace. This trace from the active CDP is
then cross-correlated with the pilot trace, forming a shift
power trace. This shift-power trace is then summed with
other shift-power traces having the same receiver and again
with those having the same shot. The above process is then
repeated for all traces in the active CDP, then the active CDP
is incremented, and the pilot-stack power process repeated
for all speciﬁed CDPs. After the shift spectra from all traces
for the entire dataset have been computed and summed in
the receiver and shot domains, time shifts are picked at the
maxima relative to the center (within the maximum allowed
time shift for that iteration) of the power shift spectra and
stored as receiver and shot statics. The CDP static
component is removed by linear (2D) or spatial (3D) trend
removal. In the next iteration, the pilot stacks are then
updated with these statics estimates and the complete
process is repeated for a speciﬁed number of iterations. After
the convergence criteria has been met or the maximum
number of iterations used, the program outputs the ﬁnal

Usage
You have the option to apply previously computed statics
before execution to allow iteration on a step by step basis, or
check pointing. If the dataset is large and execution times are
long, running one iteration at a time may be preferable to
trying multi-iterations resulting in very large elapsed times.
Since you can now set the maximum residual static value
allowed per iteration, it may be instructive to try many
attempts at the ﬁrst iteration, varying the maximum
allowable static to determine the best maximum static per
iteration. We suggestions increasing the maximum allowable
static for each iteration, but start small. Residual statics
exceeding the iteration limit value are set to zero.
In addition to the maximum number of iterations, you may
specify an RMS static change convergence criteria. If the RMS
of the change in the computed statics between iterations is
less than this value, the additional iterations are not
performed.
The program includes a parameter for the percentage of live
samples in a gate. If less than this percentage of the samples
in any gate are non-zero, the gate is excluded from the
residual static estimate. Zero sample values normally result
from NMO stretch muting or surgical mutes.
The correlation reject option scans the correlation to ﬁnd the
values of the two largest peaks. If these values are NOT
different by a user speciﬁed percent, the correlation is
rejected, that is, it does not enter the source correlation stack
or receiver correlation stack. This option will reject
correlations contributing to cycle skips.
You can optionally use the positive envelope of the stackpower traces before source and receiver accumulation. This
option may be useful on datasets with cycle skips on the
brute stack.
You can also restrict the offsets of traces used in the
computations, if the data has serious ground roll or other
offset separable problems.

The dataset used for computation may be restricted by CDP
number or by start and end inline and crossline.
You must specify ﬁnal minimum and maximum static values
allowed. Any source or receiver static that exceeds these
values will be set to zero.
It is critical to remember that CDPs used in the solution will
be enclosed by the geometry of the entries in the Autostatics
Horizon ﬁle. Typically, to use all CDPs (entire survey in 3D)
the autostatics horizon ﬁle deﬁnition points must include the
ﬁrst CDP of the ﬁrst inline, the last CDP of the ﬁrst inline, the
ﬁrst CDP of the last inline and the last CDP on the last inline
(if the survey is oriented N-S-E-W). However, this may not be
enough points to include all the edge CDPs (with oblique
surveys). We suggest that the start and end CDPs of
intermediate inlines also be picked to ensure the whole
survey. If the autostatics horizon is only desired over a part of
the survey, we suggest that a minimum of 4 points be used in
the horizon deﬁnition.
The CDP term may be optionally 1) removed after each
iteration (default), 2) removed after the last iteration (if more
than one iteration is speciﬁed) or 3) NOT removed at all. In
2D, if the length of the smoother is speciﬁed equal to or larger
than the total number of CDP’s in the line, a straight line is
ﬁtted to the source statics and another line is ﬁtted to the
receiver statics. The static values are adjusted so that the
lines are ﬂat (horizontal) at y = 0 (no static bias). If, in 2D, the
length of the smoother is LESS than the total number of
CDP’s in the line, a low frequency source static component is
computed using the speciﬁed length of smoother. The low
frequecy component is subtracted from the original source
statics. The same process is applied to the receiver
statics.The same adjustment occurs in 3D, except 2
dimensional ﬁlters are used as speciﬁed in the menu. The
(old and new) default length is (NILINESz + NXLINESz) / 2. on
each side. This trend is computed for both source and
receiver statics and the trend values are subtracted.

Parameters
Select Trace data ﬁle
Select an NMO-corrected CDP gather trace dataset from the
datasets menu.
Select Autostatics horizon ﬁle
Select an Autostatics horizon ﬁle from the horizon ﬁle menu.
This ﬁle should contain time gates for the autostatics
reference horizons.
RMS static change convergence criteria
Enter a check for the convergence of the solution.
Calculations are terminated if the RMS of the change in
computed statics between iterations is less than this value.
Enter 0.0 to disable this feature.
Maximum number of iterations
Enter the maximum number of iterations. Only this number
of iterations are performed if the RMS static convergence
limit is never satisﬁed.
