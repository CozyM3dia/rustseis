Surface Consistent Amplitudes
Surface Consistent Amplitudes estimates and adjusts the
relative amplitude contributions of sources, receivers, offset
bins, CDPs and channels, on a surface consistent basis.

Theory
The amplitude of any trace is a combination of a number of
factors. These include the strength of the shot, the response
and coupling of the receivers, the performance of the
ampliﬁer channel, the offset of the traces, the density and
velocity contrasts of the reﬂecting horizons, and other more
ambiguous factors, such as ambient noise. While it is
difﬁcult to separate these effects on a single trace, they can
be estimated statistically from many traces. For example, the
traces of a particularly weak shot will tend to show lower
than normal amplitudes. All traces recorded at a certain
ground station can be of higher amplitude because of better
than average geophone coupling at that surface location. One
or more channels may differ in response from the average.
Typically CDP, Offset Bin and Channel are not surface
consistent domains.
This tool is a three-pass process: Input, Compute and Apply.
The last two passes may be combined.
Input mode
This is the ﬁrst pass. It estimates the amplitude for each
input trace over a speciﬁed time gate and writes the
amplitude to the TRC database.
Amplitude is estimated in a time gate. One and only one time
gate per trace must be speciﬁed, but the gate may vary
spatially along the line. If the time gate for a trace is less than
a minimum threshold length, parameter Minimum gate
width, the program resets the gate to the minimum length.
The reset time gate is centered on the starting time of the
original gate.
The program can compute statistical amplitude estimates by
the following methods:

1. Use the mean of the absolute amplitude of all nonzero
samples in the gate.
2. Use the RMS of all nonzero samples in the gate.
3. Use the median of a set of mean amplitudes computed for
21 subgates of the instantaneous amplitude envelope
trace. Here is what happens for this option:
• Compute the instantaneous amplitude envelope trace
using a Hilbert transform.
• Divide the gate into 21 expanding subgates. Subgate 1
contains the ﬁrst 1/21 samples of the gate, subgate 2
the ﬁrst 2/21 samples, and so on.
• Compute the mean of the amplitude envelope of all nonzero samples in each subgate.
• Use the median of the 21 subgate amplitudes as the
value for this trace. Only subgates containing nonzero
values are used to derive the median.
Compute only mode
This is the second pass. It is a stand alone process and does
not input or output traces. Instead, it reads the initial trace
amplitudes from the TRC database, decomposes them into
the desired components, and writes the component
amplitudes to the SIN, SRF, OFB, CDP and CHN databases.
The ﬁrst step in decomposition is to create initial amplitude
estimates for each source, receiver, offset, CDP and channel.
The program creates the initial estimates by combining the
amplitudes of all traces that contribute to each component.
The program can combine trace amplitudes by the following
methods:
1. Use the mean of all trace amplitudes within a range of
minimum and maximum amplitudes.
2. Use an alpha-trim mean of all trace amplitudes.
The program uses a Gauss-Seidel iterative inversion method
to decompose the initial amplitude estimates. This approach
is very similar to the one used to calculate surface consistent
static corrections. After the last iteration, the ﬁnal amplitude
solutions are written to the database for quality control
and/or subsequent application.

Apply only mode
This is the third pass. It applies amplitude adjustments to
the input traces. You may apply amplitudes from any or all of
the components. If you elect to apply gains from all ﬁve
components, the program multiplies each trace sample by
1.0 / (SRC_GAIN * RCVR_GAIN * OFFSET_GAIN * CDP_GAIN * CHAN_GAIN)

If the amplitude for a component index is null, a gain of 1.0 is
used for that component.
Compute and Apply mode
This combines the second and third passes.

Usage
Input prestack traces may be in any order. They should have
true amplitude recovery applied to them.
Input mode may be run many times with Yes to Add to
existing trace amps to input portions of the trace volume as
they become available and accumulate amplitudes in a single
TRC AMP_COMP AMPLxxxx database attribute. Then
Compute only mode decomposes all trace amplitudes into
the desired components.
Surface Consistent Amplitudes causes output trace
amplitudes to be near unity, 1. If amplitudes closer to those
of the input data are desired, use Trace Math after Surface
Consistent Amplitudes to multiply by a scalar equal to the
average amplitude of all the input traces. This average
amplitude value can be obtained from Amplitude Scanning
or by visual inspection of the TRC AMP_COMP AMPLxxxx
database attribute.

Using OTHER, a user-deﬁned component
You can use OTHER in addition to or as a replacement for
the standard components. You can use any header word in
the input trace headers with INTEGER format to deﬁne the
OTHER component. You must choose which header word to
use before Input mode because during Input mode the
program creates database attributes that are needed to
include OTHER in the decomposition.
If, during Compute mode, you decide that you don’t want to
use the OTHER component, simply drop it from
Components of amplitude decomposition. However, if you
decide that you want to use a different header word for
OTHER, you must rerun Input mode to create a new set of
database attributes.

Parameters
Mode of operation
Select the mode of operation from:
• Input inputs traces, computes amplitude estimates, and
writes trace amplitudes to the database.
• Compute only computes surface-consistent component
gains and writes them to the database.
Note: In this mode the tool is stand alone and should be
the only tool in the ﬂow.
• Apply only applies previously computed component
gains to the input traces.

Input parameters

Type of amplitude computations
Select the type of amplitude estimation for each input trace
from:
• Absolute values of samples uses the mean of the absolute amplitude of all nonzero samples in the analysis

Analysis gate reference time
Select from:
• Time zero to have gate times referenced to time zero.
• Water bottom to have gate times referenced to the
water-bottom time. The value of trace header entry
WB_TIME is added to gate start and end times. For
example, if the start time from the menu or gate ﬁle is
500 ms and the value of WB_TIME in the trace header is
300 ms, the design gate starts at 800 ms.

Enter the minimum width of any analysis time gate in ms. At
some far offsets, there may not be sufﬁcient live samples

minimum gate width is reached, the gate is expanded above
and below the gate start time to this minimum width.
