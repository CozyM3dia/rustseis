Refraction Statics Calculation*
Refraction Statics Calculation* computes refractor velocity,
refractor delay time, depth model, and shot and receiver
statics.

Theory
The basic assumption is that weathered material exists below
the source and receiver satisfying the delay time model. There
are no shooting geometry restrictions, the method is
applicable to 2D, 3D, or crooked lines. You do not need to
pick ﬁrst breaks for all the sources, however, enough correct
ﬁrst break picks must be available for a minimum fold for
receivers. The ﬁrst break picks in the TRC database for the
unused sources must be RNULL or less than or equal to zero.
All database attributes are expected to be complete and
accurate. Errors in ﬁrst break time picks and shooting
geometry will degrade refraction statics results. Source
depth, uphole time, elevation, X and Y values are needed
from the SIN database. Receiver elevation, X and Y are
needed from the SRF database. Trace SIN, SRF, sourcereceiver offset, ﬁrst break time picks, and CDP values are
needed from the TRC database. The maximum number of
layers allowed is 5, however, experience shows that one easily
picked layer usually provides a better solution than two
uneasily picked layers.
The seven main stages in obtaining a statics solution are:
• Stage 1: Input or compute V0, interpolate, and place in
SIN database, and make each ﬁrst break time surfaceto-surface.
• Stage 2: Input or compute refractor offset data, spatially
interpolate if necessary, place in SIN database.
• Stage 3: Compute refractor velocities and output the
values to the SIN and CDP databases,
• Stage 4: Compute source and receiver delay times by
iterative delay times or DRM, optionally update refractor
velocities (iterative delay times), and output to the SIN,
SRF and CDP databases.

Note: V0 is the weathering velocity. It will be used as the

Each stage may be done separately to allow you to edit V0,
refractor offsets, refractor velocities, delay times depths or
statics using database display, or all ﬁve stages may be
performed at once. The delay time method requires surfaceto-surface travel times, so source uphole time is added to all
traces belonging to that source. Offset values used in the
velocity and delay time estimates are three dimensional
offsets computed from source and receiver X, Y, and elevation
coordinates.
Note: For 64 bit platforms, different results will appear for
database values computed from the stage by stage usage as
compared to the all stages ON usage. This is due to each
value written to the database being converted to IEEE format
prior to disk output (truncation to 32 bits), then re-read and
converted from IEEE format to 64 bit representation. This
effect is most severe when velocity is iterated in the delay
time stage.

Usage
Refraction Statics Calculation* expects ﬁrst break time
picks to exist in the TRC database. This may be done using
any one of the many ﬁrst break picking tools available with
the ProMAX® processing system. If your data has high fold
you may only need every second or third source with usable
picks. There is no substitute for correct ﬁrst break time
picks.

Stage 1: Input or Compute V0
Refraction Statics Calculation offers three options for
weathering velocity (V0) deﬁnition.
• Option 1: Compute V0 from source depths and uphole
times for shot source acquisition.
• Option 2: Input V0 from menu (user typein). If source
depths are available, uphole times will be computed
using the user speciﬁed V0 and the source depths.
• Option 3: Input V0 from menu (user typein). Use uphole
times from the SIN database to correct ﬁrst break times
to surface.
Accurate uphole times are needed to convert ﬁrst break times
into surface-to-surface travel times for correct delay time
estimates. If the source was at the surface, no uphole
information is available, and you must type in a best estimate
of SIN vs. V0.
Stage 2: Refractor Offset Deﬁnition
Refraction Statics Calculation offers four options for refractor
offset deﬁnition.
• Option 1: Create a Mute ﬁle using a ﬂow applying LMO

Display. Use one mouse click for the start and one for

refractors on each selected source. This Mute ﬁle name

• Option 2: Visually determine the refractor offset ranges
on selected, LMO sources and write down the SIN and
offset ranges for each refractor. Whether you use a Mute
ﬁle or type in refractor offset deﬁnition, the missing SINs
are provided with values by interpolation using x,y coordinates. The number of layers (refractors) is a parameter
needed in the menu.
• Option 3: For 3D only, use the ﬁle generated by 3D Ref.

• Option 4: Automatic refractor offset computation for the

Stage 3: Compute Refractor Velocity
The next stage is to input all source, receiver and CDP
geometry, optional source uphole information, ﬁrst break
time picks, refractor offset deﬁnition, and compute refractor
velocity for each SIN that meets the minimum fold criterion.
The program ﬁts either least squares or median lines to the
picks in the refractor zone for velocity estimates. Optionally,
the standard deviation of pick time variation from the median
line may be used to detect and kill (RNULL) bad picks and
recompute velocity. The updated ﬁrst break picks are written
to the TRC F_B_PICK database if the process has killed any
ﬁrst break picks. Velocity values for SINs are projected into
CDP, optionally smoothed and written to the CDP database
(VCINITNM) and projected back into SIN and written to the
database (VSINITNM). The N refers to the layer number and
the M refers to the identiﬁcation number. These CDP velocity
values will be used in delay time decomposition in stage 4.
Long operator smoothing of the initial refractor velocity
estimates is strongly recommended to stabilize the low
frequency static component. The auto-edit option restricts
refractor velocity to a speciﬁed percent of the median value
for the whole refractor and kills (RNULL) ﬁrst break picks
responsible for the bad velocity values and writes the
updated pick ﬁle to the TRC database. Examination of SIN
refractor velocities without the auto-edit option is a quality
control step showing which SINs have bad picks, wrong
geometry. or what produced anomalous values. The problems
with the sources may be corrected and this stage rerun.
Stage 4: Compute Delay Times
Once CDP velocity is available, delay times may be computed
by one of two methods: Iterative Delay Time or DRM
(Diminishing Residual Matrices / Domain Averaging).

• The Iterative Delay Time solution begins with source
delay time estimates, followed by receiver delay time estimates, and optionally ﬁnalized by refractor velocity
reﬁnement. Refractor velocity is reﬁned by subtracting
the current receiver delay times from the ﬁrst break
times and ﬁtting a least squares or L1 norm line to the
corrected ﬁrst break times. Values are not computed for
any source or receiver that does not meet the minimum
fold criterion. Once the decomposition is complete for
each refractor, these missing values are interpolated
based on X and Y. If velocity iteration is selected,
medium to heavy smoothing between iterations is recommended, especially for low fold data. Source delay time
values are written to the SIN database as SDELAYNM
where N is the layer number and M is the identiﬁcation
number. Receiver delay times are written to SRF as RDELAYNM, and ﬁnal refractor velocities are written to CDP
as VCFIN0NM. Source and receiver delay time descriptions include the GS term indicating a Gauss-Seidel
solution. All delay time and velocity values may be
viewed and edited in database display.
• The DRM method starts by applying LMO to each eligible
time to remove the offset term of the delay time equation.
The velocity at the trace CDP location is used for LMO.
The velocity corrected times are loaded into a matrix
with common source across (row) and common surface
location down (column). The sum of the magnitude of all
the matrix elements is computed and printed before
each iteration. A source iteration consists of summing all
times that belong to a source (across a row) and assigning half the sum to the delay time accumulated for that
source. This is done for all sources. Similarly, a receiver
iteration consists of summing all times for a surface
location (down a column) and assigning half the sum to
the delay time accumulated for that receiver. The iteration is ﬁnished by subtracting the source and receiver
time contribution (from that iteration) from each element
in the matrix (diminish the matrix), and the new sum of
magnitudes computed and printed. With this method,
most of the delay time for a source or receiver is computed in the ﬁrst iteration. Subsequent iterations adjust
the distribution of time between source and receiver. No
velocity iteration is done. After the ﬁnal iteration is complete, source and receiver delay times are written to the
database with DRM included in their descriptions. The

Stage 5: Compute Depth Model
This stage inputs delay times and refractor velocities in CDP,
interpolates refractor velocity into SIN and SRF, computes a
depth model for sources and another for receivers, and writes
the depth values into the SIN REFDEPTH SDEP_0NX and
SRF REFDEPTH RDEP_0NX attributes. Optionally, the ﬁrst
refractor depth or elevation in SRF may be projected into
CDP, smoothed, projected back into SRF, V0 recomputed in
SRF based on the smoothed depths or elevations, new V0
projected from SRF to SIN, and ﬁnally SIN and SRF depth
models computed. REFDEPTH is the depth below surface
elevation.
Stage 6: Compute Source and Receiver statics to ﬁnal datum
This stage inputs refractor velocities and refractor depths,
computes source and receiver depths to ﬁnal datum and
outputs static values into the SIN Geometry SSTAT and SRF
Geometry RSTAT databases. Time from bottom of the depth
model to ﬁnal datum may be computed with a constant
velocity from the menu or bottom refractor velocity.
Stage 7: Compute Residual Source and Receiver statics at
smoothed surface
This stage inputs refractor one (1) velocity and source and
receiver statics to ﬁnal datum and computes residual source
and receiver static values at processing datum and outputs
to the SIN Geometry S_RESIDN and SRF Geometry
R_RESIDN databases. The computational process involves:
• Applying source and receiver statics to the ﬁrst break
picks from the ﬁrst refractor, then adding another CDP
consistent time shift to place the datum at the processing datum.
• Applying linear moveout to each ﬁrst break time based
on CDP velocity of the ﬁrst refractor.
• Using DRM to compute source and receiver components
of the static-corrected, moved-out ﬁrst break times
• Removing the low frequency trends of the source and
receiver components by subtracting a smoothed version
of the components from the original.
